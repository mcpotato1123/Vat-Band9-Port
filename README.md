# 《拆迁地球及爱情事故》· 小米手环 9 Pro 版

把 PC 版 Ren'Py galgame **Is the Vat Utopia or Dystopia?** 移植成能在**小米手环 9 Pro**（336×480 矩形 AMOLED）上跑的 **Vela 快应用**。

**引擎与界面**

> 界面照 [xuanyide01/steins-rw5](https://github.com/xuanyide01/steins-rw5)（《命运石之门》REDMI Watch 5 版）—— 顶部信息条 + 画面区 + 对话框、白条按钮、硬边卡片、粉红强调色。
> 工程结构照 [mcpotato1123/galgod-band](https://github.com/mcpotato1123/galgod-band)（GalGod 手环 9 Pro 版）—— `designWidth 336`、PNG 调色板、只用 `protected`、`rgba()` 不用 `opacity`、JSON 存 `.txt`、aiot-toolkit 构建。

```

产物      dist/com.port.vat.band9.release.1.0.0.rpk（10.10 MB，已签名）
```

## 故事梗概

> 以下为原作设定的简介。

**世界观**

银河市建设与交通部发布通告：因「英仙区到人马区间猎户分区」曲境高速公路工程，**太阳系将被拆除**。
三分钟后，四十二星际建设公司高级工程师**基伯·卡当**抵达地球，执行「地球生命切片计划」——
抽签选中的两个人，要在拆迁前作为人类样本被保存。

**主要角色**

| 角色 | 简介 |
|---|---|
| **陈蝶蕊**（少女） | 被抽中的少女。嘴很臭，会自称「美颜拍出来就这样」，反感别人叫她「地雷女」。 |
| **许清北**（主角） | 她的同桌。只想安安静静上完这堂课，却一次次被卷进她的麻烦里。 |
| **基伯·卡当** | 拆迁项目责任人，西装革履，说话永远像在念公告。 |
| **奥罗拉** | 出现在主角身边的另一名少女，身份与「切片计划」有关。 |

**主线**

地球还剩三宇宙年。拆除通告、生命切片、抽签结果——本该是天塌下来的大事，
可教室里的日常还在照常进行：早读、天台、放学后的街道。
少女们关心的不是人类存亡，而是「你刚才是不是在敷衍我」。

故事就在**拆迁倒计时**和**恋爱事故**之间来回摇摆，
直到最后所有人都必须回答那个问题：这个地球，到底是乌托邦，还是反乌托邦。

## 二、构建

```powershell
npm install                 # aiot-toolkit 2.0.5
npm run check               # 排版 + 几何 + 全剧走通
npm run build               # -> dist/*.debug.*.rpk
npm run release             # -> dist/*.release.*.rpk（需要 sign/）
npm run preview             # -> preview/*.png
```

从原作素材重新生成（需要把原版 `archive.rpa` 解包到 `../解包/`，脚本里的路径按需改）：

```powershell
python tools/gen_story.py       # .rpy → 分块 + assets.js + art.json
python tools/gen_assets.py      # 立绘/背景/CG → 手环尺寸 PNG
python tools/make_ui.py         # 标题背景 / LOGO / 按钮 / 图标
```

### 签名

`npm run release` 需要 `sign/private.pem` 与 `sign/certificate.pem`（不进仓库）。生成方式：

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-sign.ps1
```

脚本用 .NET 的 `CertificateRequest` 直接生成 RSA 2048 自签名证书，不依赖 openssl。
**自签名只保证包内有签名块（`META-INF/CERT`），不代表小米应用市场的签名链能验证通过**——
装不上就换 `debug` 包，它本来就不需要签名。

> `aiot` 每次构建都会清空 `dist/`。要同时留 release 和 debug，先构建 release 把 rpk 挪出去，再构建 debug。

## 四、运行时的设计

### 屏幕与单位

`manifest.json` 里 `designWidth: 336`，而 9 Pro 物理宽就是 336，所以 **1 css px = 1 物理像素**，CSS 直接写像素、不做任何换算。

```
0   ┌──────────────────────┐
    │ 第一章·第一幕  34%  ≡ │  32px 信息条：14px 章节 + 12px 进度 + 30px ≡
 32 │                      │
    │   背景 336×220       │  16:9 裁两侧铺满
    │   立绘 143×220 ×3    │  头→腰整段铺满，腰线压在面板上
252 ├──────────────────────┤
    │ 陈蝶蕊               │  说话人 258
282 │──────────────────────│  分隔线
288 │ 借给收入为零的家伙…   │  正文 6 行（18px/22px 行高）
480 └──────────────────────┘
```

### 画面分层

从下到上：`背景 → 立绘槽 0/1/2 → 信息条 → 进度条 → 点击层 → ≡ / ▼`，对话面板是画面区之外的同级节点。
每个剧情节点自带**完整画面状态**（`bg` + `sp` 数组），引擎每句话整体覆盖三个槽位，不做增量推断——这样不会出现上一句的立绘残留。

### 剧本数据格式

`src/common/story/index.txt`：

```json
{"v":1,"total":6975,"chunkNodes":400,
 "chapters":[{"id":"c1r1","title":"第一章 · 第一幕","start":0}, …],
 "chunks":[{"f":"chunk-000.txt","start":0,"n":400}, …]}
```

节点类型（键名极简以压体积）：

| t | 字段 | 语义 |
|---|---|---|
| `s` | `n` 说话人、`x` 台词、`bg` 背景下标、`sp` 立绘 `[[槽位,下标],…]`、`cg` 若当前背景是 CG | 一句话 |
| `o` | `p` 提示、`o:[{x,j}]` | 选择分支 |
| `j` | `j` | 无条件跳转（编译期已解析成节点下标） |
| `e` | — | 结局 / 本章结束 |

分支是**编译期展平**的：菜单的每个选项生成独立标签，选项体执行完跳回汇合点，运行时只需要认「跳转下标」，不需要解释器。

### 交互与阅读设置

- 轻触画面：文字没打完 → 立即补全；本页读完 → 翻页或下一句
- 右上 `≡` 或右滑：打开阅读菜单（保存 / 读取 / 自动 / 快进 / 设置 / 标题 / 退出）
- 系统返回键：开 / 关阅读菜单，不会误退出
- 打字机用 50ms 时间校正 + token 取消，切句 / 重排 / 隐藏都会让旧回调自弃
- 设置：字号 15–24、播放速度 0–120ms、自动间隔 0–200ms、屏幕常亮

### CG：拖动看全图

剧情里的 CG 是 336×220（裁切版）；鉴赏页另存一份 **533×300 全图**，放在 336 宽的裁切窗口里横向拖动：

```js
this.bigLeft = clamp(dragFrom + (x - dragX), MIN_LEFT, MAX_LEFT)   // MIN=-197, MAX=0
```

三条路都留着：`ontouchmove` 跟手拖、`onswipe` 每次跳 90px（固件不派发 touchmove 时兜底）、底部 `‹ ›` 切差分图。
坐标字段按 `clientX → pageX → x → offsetX` 兜底，`touchend` 读 `changedTouches`。

### 章节选择

只列 10 个正篇章节；`byebye`（「我不认可」触发的告别支线）在 `index.txt` 里标了 `hide:1`，不进列表但可从警告页直接跳入。

### 内容警告与退出确认

点「开始」先弹内容警告（原作的 `screen warning`）：三角 + 「注意」抠图 + 手环可读的 11px 正文 + 原作 `我认可捏` / `我不认可` 按钮。
「我不认可」不会退出，而是进入原作 `script_test.rpy` 的 `label byebye`——那段角色出来吐槽「这题材的游戏肯定没人玩」的剧情。

退出走二级确认：`是否要退出游戏？` + 原作 `确认/取消` 的 ○ / ✕ 圆形图标。

## 五、已知的坑（都已在代码里绕过）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 标题 6 个按钮叠在一起 | Vela 的 `<div>` 默认 `flex-direction: row`（不是 Weex 的 column） | 菜单改绝对定位，每行自带 `top` |
| 2 | 阅读菜单 7 项叠在顶部 | 同上 + 模板漏绑 `style="top: {{$item.top}}px"` | 补绑定 |
| 3 | 设置页 6 行挤成一行 | `.rows` 缺 `flex-direction: column` | 改绝对定位 |
| 4 | 退出确认文字与 ○✕ 横排 | `.confirm` 缺 `flex-direction: column` | 补上 |
| 5 | 章节页空白 | `<list>` / `<list-item>` 在该固件上不可靠 | 章节/存档/关于全部改绝对定位分页 |
| 6 | `onclick` 编译报错 | 事件参数只接受裸标识符或数字，`{{...}}` 和字符串字面量都会失败 | 统一 `fn($idx)` + 处理函数查表 |
| 7 | `object-fit` 无效 | aiot 2.0.5 不认该属性 | 图片按目标尺寸给死，超出用 `overflow: hidden` 裁 |
| 8 | 立绘一大一小 | 素材取景不同（全身 / 腰上 / 特写），按盒子 contain 后头部差 40%+ | 按内容统一裁到「头到腰」再等比铺满 |
| 9 | 立绘浮空（脚下留背景） | 画布比画面区高，宽度受限的立绘够不到面板线 | 画布等于画面区，**底边对齐** |
| 10 | CG 场景出现两个同一角色 | CG 是全屏插画、画里已有人，立绘又叠上去 | 编译期：背景是 CG 时强制清空立绘 |
| 11 | 教室同屏两个陈蝶蕊 | 中文命名立绘（`陈蝶蕊全身`）没有角色前缀，落到默认槽位 | 建中文名 → 角色代码的槽位映射表 |
| 12 | 第一页两个陈蝶蕊 | `模糊1/模糊2` 是景深虚化副本，被当成独立角色 | 编译期跳过 `模糊*` 素材 |

## 六、和参考工程不一样的地方（以及为什么）

- **不用 `<list>`**：galgod 用 `<list>` 做滚动列表，实测在该固件上渲染不出来（章节页全白），所以章节 / 存档 / 关于全部改成「3 条一页 + 绝对定位 + 翻页条」。设置页是唯一保留 `<scroll>` 的地方，且所有控件都在第一屏，滚不动也能用。
- **CG 上绝不叠立绘**：原作 CG 是全屏插画，画面里已经画了人；我们的引擎没有图层概念，叠上去就是重影。
- **立绘裁到「头到腰」**：画面区只有 220px 高，整张全身像缩进去人物会变得很小；统一裁到上半身再铺满，至少不会一大一小。
- **背景裁两侧**：原作是 16:9，手环是竖屏。选择「裁掉左右 30% 铺满 336×220」而不是「上下留黑边」，因为黑边在小屏上太显眼。
- **分支编译期展平**：运行时不带解释器，菜单选项在编译时变成固定跳转，省内存也省心智。

## 八、操作提示

- **标题页**：点「开始」→ 内容警告 → 认可后进入正文；「继续」读自动存档；还有章节 / CG / 设置 / 退出
- **正文**：轻触推进、点右上 `≡` 开菜单、右滑也可开菜单、系统返回键开关菜单
- **存档**：30 个栏位，3 栏一页；游戏内「保存进度」会跳到选栏页
- **CG 鉴赏**：默认全解锁；点开大图后左右拖动看全图，`‹ ›` 切差分，右上圆形 × 关闭
- **卡顿时**：设置里关掉「自动播放」、字号调小一档，能明显减少重排
